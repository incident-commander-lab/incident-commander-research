Phase 3 · Research direction

Existing Autonomous SRE Platforms and Their Autonomy Models

Current commercial platforms demonstrate that autonomous incident response is already moving into production. Therefore, the Phase 3 research opportunity should not be framed simply as enabling autonomous remediation. Instead, existing mechanisms for controlling autonomy should be examined to identify remaining gaps.

Platform Autonomous capabilities How autonomy is controlled Main limitation / open question
Microsoft Azure SRE Agent Incident investigation, troubleshooting, mitigation, and autonomous execution Review vs. Autonomous modes, response plans, permissions, and task/incident configuration Autonomy is primarily configured by humans rather than dynamically adapted from verified operational outcomes
AWS DevOps Agent Autonomous investigation, root-cause analysis, and remediation workflows IAM permissions, permission boundaries, approval actions, and controlled remediation workflows Strong permission controls exist, but the autonomy boundary is primarily policy/configuration-driven
Datadog Bits Investigation and remediation such as scaling deployments, restarting pods, and modifying resources Ask/Deny guardrails based on action, environment, service, and resource Guardrails define what the agent may execute, but publicly documented behavior does not show an outcome-driven mechanism for automatically expanding or reducing authority
Dynatrace Intelligence Investigation, causal analysis, and execution of approved remediation workflows Policies, permissions, and approved runbooks/actions Autonomy is bounded through predefined policies and workflows rather than an explicitly outcome-driven autonomy mechanism
PagerDuty / Agentic Incident Response Automated investigation and incident-response workflows Workflow configuration, governance, and approval mechanisms Supports increasing automation, but adaptive authority based on accumulated operational evidence is not the central mechanism

Key observation

Existing platforms show that the industry has moved beyond a simple “AI recommends, human executes” model. Autonomous execution is already available in several commercial systems.

However, the dominant control pattern is:

Human defines the boundary → agent operates within the boundary.

A potential alternative is:

Agent operates within hard safety boundaries → outcomes are verified → operational reliability is measured → autonomy is adjusted within those boundaries.

This motivates the Phase 3 research direction.

Proposed research opportunity

The proposed research question is:

Can an SRE agent dynamically adapt its operational authority per action or incident based on verified operational outcomes, while remaining within hard policy and safety constraints?

A broader version is:

Can reliability, risk, reversibility, and cost jointly determine the appropriate autonomy level of an SRE agent?

This would extend Incident Commander from:

  • Phase 1: What evidence should the agent collect next?
  • Phase 2: Does the agent have enough evidence and authorization to act?
  • Phase 3: How much authority should the agent have for this type of action or incident?

The objective is not to maximize autonomy, but to:

Increase autonomous coverage without increasing harmful actions or allowing operational cost to become uncontrolled.
